## Version/freshness mechanics
Synchronous projection reads capture one engine task without awaits/writes/provider calls. Revision changes only when projected facts/config-selected freshness policy/lifecycle change; not every capturedAt. On normal usage/state/config changes update status; final ordinary liveUsage result retained then updates cursor. A single engine-owned unref timer fires at earliest known quota-age/window reset or credit freshness/expiry deadline, advances cursor on actual freshness changes; no timer per subscriber/provider fetch. Conditional reads also recompute time transitions for synthetic clocks. Shutdown clears timer/retained context state. Restart new epoch.

## Frozen implementation refinements
Quota windows expose `reportedAvailability` and retain raw percentages even when stale; overall `availability` is unknown when no general window was reported. Reported quota headroom is not credential-validity proof. Unknown auto/session-log Codex provenance stays `accountAttributed:false`; account-scoped saved probe facts can retain positive attribution even without a source tag.

Native attribution requires current identity, retained profile ownership, and matching selected saved profile. Saved-account rows may use a matching, positively attributed native cache to fill a missing account cache, only for that exact saved owner. Native credits use the retained identity-matched reading; toolbar uses the same pure helper without a selected-profile fallback. Quota expiry does not independently expire credit evidence.

Copilot retention is scoped to each client context. Both context setter paths, disconnect, and `copilot.account` changes invalidate old facts. An ordinary read completing after context/account replacement cannot restore them. Account filters preserve total saved count but withhold native details unless its saved profile is included; unsaved native details are withheld with an account filter.

Malformed latest reported-credit metadata cannot fall back to an older known count. Invalid timestamp ordering is conservatively unknown; malformed or expired expiry cannot become known. A single captured clock governs each projection. Timer scheduling only uses future deadlines. Every real configuration revision, including rotation policy changes, advances the cursor; capturedAt alone does not.
