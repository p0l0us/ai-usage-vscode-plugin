# W21M MCP status wire contract — design for review

Implementation waits for W21E/W22 agreement. Ownership: service/src/mcp.ts, service/test/mcp.test.js, docs/MCP.md only. W20 is frozen and accepted. No adapter code changed by this proposal.

## Existing negotiation and official wire

Current source exports exactly 2025-06-18, 2025-03-26, 2024-11-05; initialize echoes a supported request or offers 2025-06-18. Retain these versions, with no 2026 migration. Add resources: {subscribe:true,listChanged:false} alongside existing tools capability. Standard methods resources/list, resources/read, resources/subscribe, resources/unsubscribe and notification notifications/resources/updated {uri} apply to these supported versions. Resource reads return contents [{uri,mimeType:'application/json',text:JSON.stringify(value)}]. Subscribe/unsubscribe return {}. Notifications carry invalidation URI, never account data or credentials. initialize and notifications/initialized remain the handshake; delivery starts after initialized. Titles are optional metadata, not required wire fields for older clients.

Official primary sources: https://modelcontextprotocol.io/specification/2025-06-18/server/resources ; https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/2025-06-18/schema/2025-06-18/schema.ts (SubscribeRequest, UnsubscribeRequest, ResourceUpdatedNotification); https://modelcontextprotocol.io/specification/2025-03-26/server/resources ; https://modelcontextprotocol.io/specification/2024-11-05/server/resources . Cancellation uses notifications/cancelled {requestId} under the negotiated protocol, not a new event schema.

## Resource identity and validation

List four stable resources: ai-usage://status and ai-usage://status?provider=claude|codex|copilot. Descriptions explain toolbar facts, saved counts/all saved rows, separate native row, cached readings and unknown/stale reset credits. No dynamic list_changed claims, account-name enumeration or account template platform. An optional account=<saved-id> query filters saved rows; account IDs are opaque store IDs, never names/emails/paths. Account filter requires provider. Keep total savedAccountCount unchanged by filter; native row remains separately attributed by engine; an account filter hiding the saved active account hides its native profile ID/quota/credits too (native unknown). Removed/nonexistent saved ID gives an empty saved list, not another account fallback.

Reject unsupported scheme/host/path/fragment, unknown or duplicate query keys, invalid provider, empty/over-128-character account ID, URI over 1024 bytes. Canonical query order provider then account, encoding through URLSearchParams; reject noncanonical identities so subscriptions cannot alias/bypass limits. URI filtering maps to engine {providers:[provider],accountIds:[id]}. Filters are connection-local, never shared between MCP clients.

## Cache-only projection and consent policy

Use W21E statusSnapshot({providers?,accountIds?,since?}) only; never snapshot(), liveUsage(), refresh(), native probes or provider fetches. Engine StatusSnapshot is authoritative for epoch/revision, capture time, lifecycle, raw + rounded usage, freshness/deadlines, per-account credits known/stale/unknown, native saved/unsaved/unknown/none, context isolation and total saved counts. Missing credit count is unknown, not zero; stale lastReportedAvailableCount is history, not spendable credit. No client computes pooled credits or substitutes quota-window freshness for credit freshness.

Resource/tool full status payload is { ...engineSnapshot, rotationPolicy }; rotationPolicy is the existing helper from a current getConfig read, always includes both providers even when rows filtered. W21E includes configRevision in its status digest/cursor so every real policy toggle invalidates status. This is another local cached socket read, never provider collection. No settings/credential mutation. Preserve W20 ask-user-before-sustained-selection instructions; occasional switch_account remains allowed. Update W20 scheduling facts to describe implemented status events, while continuousSelectionProvided=false and automaticModelWakeupProvided=false stay truthful. Enablement is checked on every read/subscribe/tool and before outgoing delivery. mcp.enabled=false clears resource registrations and cancels waiting tools; re-enable requires explicit resubscription. Resource errors distinguish invalid params (-32602), unknown resource (-32002), unavailable/disabled service (existing internal error semantics); tools use existing isError result convention.

## Subscription, race, resync and reconnect

Maximum 8 distinct resource URIs per stdio connection. Repeated subscription is idempotent; unsubscribe is idempotent and removes pending dirty invalidation. Attach one engine statusChanged/configChanged listener per ServiceClient before taking a baseline snapshot. Store baseline per subscription; a newer event during the baseline schedules a later invalidation. This avoids subscribe/read races. No replay/history buffer or exactly-once guarantee. Client subscribes then reads current resource and retains cursor. Global revision may advance for other providers/contexts; invalidations may be conservative, never reveal that other context's facts. A single coalesced dirty marker per subscribed URI is sufficient; no intermediate revision queue. The next resource read returns latest filtered full snapshot.

On service connection loss, mark all registrations dirty and clear their old baselines. While subscriptions remain, retry the existing connect callback with one bounded unref reconnect timer (1 second, no new host/autostart path); reattach listeners BEFORE new baseline and invalidate each registration once. New engine epoch forces full resync. Stop retry when no subscriptions/waits remain or stdio closes. No credential or uncertain account mutation replay. Output close/error, input end/error and adapter.close remove listeners/timers/registrations and abort waits. Lifecycle stopping/stopped is an engine fact, not a promise that the adapter will keep the process alive.

## Minimal tools-only fallback

Add two read-only tools, keeping the existing four untouched:
- get_usage_status {providers?:['claude'|'codex'|'copilot'],accountIds?:string[],since?:{epoch:string,revision:number}} returns full cached status + rotationPolicy, or {status:'unchanged',cursor}. Engine filter limits apply: at most 3 unique providers, 40 unique account IDs, each <=128 chars; unknown keys/invalid cursor rejected.
- wait_for_usage_updates uses the same filters and required since cursor plus timeoutSeconds (integer 1..30, default 25). Maximum 1 pending wait per MCP connection. Register event listener before conditional baseline. Return immediately if cursor differs (global revision) or epoch mismatches; otherwise wait until change or deadline, then return latest snapshot or unchanged cursor. resync:true for changed epoch; an unrelated-provider event may advance global cursor, so this means state revision changed, not that the filtered account itself changed. Include timedOut:boolean on normal wait completion. No timers/provider loops outside the bounded request and shared reconnect support. notifications/cancelled and disconnect abort waits immediately and remove listeners/timers. Tool waits do not register resource subscriptions or change accounts/settings.

## Output bounds and compatibility

Coalesce resource invalidations for 100 ms, at most one pending notification per registered URI. A single stdio writer respects Writable.write(false) and waits for drain; avoid appending further notifications to the writable buffer while blocked. Bound queued ordinary responses by 64 messages/8 MiB, active input tasks by 64, and batch items by 64. On overflow or output failure terminate this adapter connection, log on stderr and abort requests rather than silently discard request responses. Existing max input message 8 MiB remains. Notification dirtiness stays bounded by 8 even under a slow reader; remove an unsubscribed URI from dirty set before drain. Responses may complete in existing out-of-order request-ID order; notification/response frames remain complete JSON newline frames. No event platform, sampling, server-requested model execution or automatic LLM wake-up.

## Acceptance and disposition

Tests use real stdio framing and synthetic engine socket hosts in background + embedded modes. Cover advertised versions/capabilities, subscribe/read/update/coalescing, validation/filter isolation, known zero versus missing/stale credits, saved counts and unsaved native, unsubscribe/disconnect cleanup, cancelled/deadline wait, race during baseline, service epoch reconnect/full resync, slow writable bounds and zero extra provider calls for reads/subscribers. Existing W20 policy-toggle/occasional-switch behavior remains intact. All tests isolated four homes, fixtureNetwork and canonical flock. W22 reviews compact contract before code, then independent frozen-source/final gate. No real account/config/install/version/index changes.
